# Agent foundation and Nike artifact design

Date: 2026-11-08. Companion brief: `docs/cloud-agent-foundation-handoff.md`.

## Intent and approach

Make Taro dependable when a user asks it to change a real project over multiple model/tool rounds. The user must be able to inspect actual changes, recover safely, continue after interruption, and trust that scoped project instructions remain available. Keep the existing minimalist visual language.

Chosen proposal: native file backups for all project folders, additional Git-tree snapshots for repository-wide capture, a durable SQLite run ledger, provider-independent summary compaction, and a scoped instruction resolver. Adapt behavior from the exact references in the brief. Whole-framework transplantation would replace Taro's architecture and is rejected. A Git-only checkpoint design would exclude ordinary project folders and is rejected. Existing Taro React/Tauri/Rust boundaries remain.

This is a design and implementation specification; the current planning turn does not change the Nike fixture or ship product code. The cloud agent first realizes the designs below in that fixture, then wires runtime behavior.

## Scope and fixed defaults

- Include changes/review/undo, long-task reliability, execution limits, recovery, automatic instructions and their artifacts. Exclude browser automation, provider migration/retry/backoff, PR publishing, automatic commits, merge/rebase UI and enterprise policy systems.
- Keep native checks and approvals authoritative. Instruction text and summaries cannot grant permissions. Preserve existing read-only children, ancestor plan restrictions and chat/workspace scoping.
- Proposed implementation defaults: 100 user-visible checkpoints per chat; 2 MiB per untracked Git snapshot file; 64 MiB new backup content per run; 256 KiB inline patch budget per file and 1 MiB per review; every limit returns a visible result rather than silently dropping coverage. Do not remove retained backups referenced by an active undo/recovery operation. Pruning is reference-aware.
- Proposed execution defaults: 128 root model requests per user turn including summary calls, existing 32-round child tool limit retained, 30-minute active execution deadline excluding time awaiting user approval. Children and compaction share root accounting; an optional dollar cap is disabled by default. Persist counters across restart. No automatic monetary claims when pricing/usage is unknown.
- Context settings per model: `contextWindowTokens?: positive integer`, `inputBudgetTokens?: positive integer`, and `maxOutputTokens: positive integer` (default 4,096). For known total window W and requested output R, usable input B = min(inputBudgetTokens if set, W - R - ceil(0.10 * W)); reject a nonpositive B. For unknown W, B = inputBudgetTokens or 16,000; this is explicitly an input-only fallback, not a claim about the provider's total window. Send the configured output limit through the existing compatible request transport. Count system guidance, current input, tool schemas, media estimates and history inside B. Use reported input usage where available and conservative estimates otherwise. Trigger compaction at 80% of B; retain up to 25% of B as newest complete exchanges. If pinned content cannot fit, block with a repairable context-too-large result; do not truncate the current request or mandatory instructions silently.
- Summary attempt policy: at most three attempts for one compaction including reduced-input overflow retries; three consecutive failed compaction operations open a circuit breaker. A successful operation resets it. Do not retry authentication/network failures as overflow. Preserve the prior valid context until the replacement commits.
- Recovery: offer Resume after restart rather than automatically executing mutations; three recovery attempts per run, persisted before each attempt. App single-instance ownership or an exclusive process lock must be established before recovering orphan claims. Never infer owner death merely from another window opening.
- Instruction includes: maximum five files deep including the entry file and maximum 32 unique files. The 32,000-character compiled guidance budget is combined across global guidance, all enabled existing workspace rules, ancestor/nested instruction files, includes and applicable conditional rules. Existing workspace-rule validation (including its 8,000-character sublimit) remains in force inside this combined budget. Excess mandatory guidance blocks generation with a per-source accounting message; no enabled rule is silently discarded. Optional absent sources are neutral, not failures. Missing explicit includes are warnings identifying reduced guidance; unreadable applicable required files block affected mutations.

## Shared row contract

- Reuse the incumbent dark surfaces, Geist/Geist Mono, purple Taro accent, semantic status colors, border token, 3.5-size icons and chevrons. Group header uses current `px-3 py-2.5 text-[13px]`; row body uses current `gap-2.5 py-1.5 text-xs`. Do not add gradients, decorative illustrations, oversized headers, new shadows or status badge walls.
- A collapsed row shows operation icon, concise verb and subject, one status, optional duration/count, and disclosure chevron. One optional muted detail line. Full paths, IDs, diagnostics, usage and multiple actions belong inside the expanded body. Truncate visually while retaining accessible full text; wrap long paths in expanded details.
- Group all operations sharing a run/tool-batch boundary. Preserve narration order; do not group across assistant prose, user decisions or unrelated runs. Lifecycle updates replace the same row ID, never append a row per progress tick. Runtime system activities count as **activities**, not falsely as tools.
- Shared states: queued, running, awaiting-approval, succeeded, unchanged, skipped, warning, blocked, partially-succeeded, failed, cancelled, interrupted. Persist operation-specific machine-readable reason separately. Keep backward mapping `done -> succeeded`; stopped is cancelled unless process outcome is uncertain, then interrupted. Preserve existing histories.
- Group precedence: running/queued work; then actionable approval/block; then failed/partial/interrupted; then warning; otherwise settled success/neutral. Cancelled/unchanged/skipped must not get a green success check. Retain any child failure indicator while another child runs. Open on first actionable state; never repeatedly override a user's disclosure choice. Settled groups default collapsed.
- Use spinner only for running; reduced motion disables animation. Status is readable without color. Disclosure buttons expose expanded state and keyboard operation. Actions are real buttons outside summary click targets, retain focus after updates, and do not nest buttons inside buttons.
- At 320px chat width and 200% zoom: no horizontal page overflow, clipped actions or hidden outcome text. Expanded output is bounded and scrollable. Announce status changes politely once; do not flood live regions with streamed output or elapsed timers.
- Put approval actions within the expanded operational row using the existing permission decision logic and IDs. Do not render a duplicate standalone permission card for the same operation. Existing unrelated tool permission cards remain unchanged.
- Use a typed action registry covering View details, Open file/document/diff, Review changes, Reload, Refresh, Retry, Resume, Continue, Cancel, Confirm restore, Restore, Redo, Stage, Unstage and Commit. Each entry specifies allowed operation/state pairs, disabled reason, whether native IO occurs and approval requirements. Display only supported actions; native commands independently validate them. A retry gets a new attempt ID under the same operation and revalidates scope/permission; it must not replay a side effect with unknown outcome.

## Review and restore semantics

Capture before-images for Write/Edit/NotebookEdit before mutation and completion state afterwards. An absent-file marker differs from zero bytes. Checkpoint failure blocks that mutation until the user explicitly chooses to continue without coverage; label the operation uncovered. Native file copies retain bytes and relevant permissions. Content hashes, canonical paths and workspace/run ownership are authoritative; mtime is an optimization only.

Serialize direct filesystem mutations, captures and restore boundaries per canonical workspace across chats/children; waiting must remain cancellable. Register every foreground/background shell as an active writer before execution, scoped to its root/child run, and retain registration until process-tree termination is verified. A launch call returning is not writer completion. Restore is blocked while any registered writer is active or has unresolved ownership; offer Stop and reconcile before preparing a new preview. Do not hold a database transaction while processes run. A Git-backed run captures before/after trees around mutating batches, covering shell changes to included files without touching the user's index, branch or HEAD. Overlapping background jobs/edits are marked mixed interval coverage, never falsely attributed to one call. External MCP changes are outside local checkpoint guarantees. Ordinary folders have tracked-tool coverage only; expose this limitation before restore.

Undo preview binds checkpoint IDs, scope, selected paths and expected current hashes to an expiring preview token (10 minutes). Approval is once-only and bound to that token; approval does not bypass a stale hash. Acquire workspace lock and revalidate immediately before restore. Save a pre-restore checkpoint, persist a restore journal, apply selected paths and record each outcome. Do not present multi-file filesystem writes as atomic. On partial failure, offer verified rollback; retain journal until resolved. No `reset --hard`, implicit clean, or automatic stash/commit.

Real Git status must parse NUL-delimited paths and handle spaces, Unicode, leading dashes, renames and deleted files. Stage/unstage selected paths only. Commit preview binds HEAD and index tree, lists exactly what will commit (including pre-staged work), and asks once. Support unborn repositories; detached HEAD commits require explicit acknowledgment. Preserve hooks/signing behavior and bound process duration. Remove fake success handlers, fake hashes and seed Git changes from real workspace routes.

## Durable execution and context

Use one native SQLite ledger for runs, ordered model exchanges, tool intents/outcomes, checkpoints, restore journals, instruction provenance, context epochs and background/child metadata. Existing UI chat JSON remains a projection; it is not the write-ahead log. Store intent before side effects and outcome after completion. Use stable run/operation/attempt IDs and transactional boundary writes. No locks/transactions held during approval or model/network waits.

A crash between side effect and outcome produces `unknown`, never auto-success or auto-retry. Read-only calls may be retried; file edits can be reconciled against hashes; shell/MCP/commit outcomes need explicit inspection. Reload the newest valid summary plus complete recent exchanges and current operational state. Missing or dangling tool results receive explicit interrupted outcomes, not invented successful content. New user input supersedes stale summary instructions.

Request limits use an atomic native reservation, not check-then-increment in JavaScript. Before any root/child/summary provider dispatch, reserve its attempt ID transactionally against the root's remaining allowance; duplicates return the same reservation. Attempted dispatch consumes a request even on network failure. Record actual/estimated usage separately and idempotently. Concurrent children at 127/128 cannot both reserve the last request. Recovery must hydrate native plan path, read-only ancestry, worktree ownership and writer guards before any tool becomes dispatchable; missing/inconsistent guard records block Resume rather than weakening restrictions.

Compaction never deletes full transcripts or output files. A summary is a context projection with coverage IDs, source epoch, model, budget estimates, usage and version. Commit only if it still covers the expected history prefix; concurrent user input stays in the tail. Reinject current instructions, workspace/worktree, active plan/mode, loaded schemas, invoked skills and task metadata within explicit budgets. Root and child context caches are independently keyed; a child compact cannot reset root state. No private reasoning in summaries or artifacts.

## Instruction precedence and delivery

User directions in the current conversation remain authoritative; files do not alter native permissions. For file guidance, compose from global Taro guidance to workspace settings rules to repository ancestor files to deeper applicable directory files; more specific guidance takes precedence for that path. In one directory load `CLAUDE.md`, `.claude/CLAUDE.md`, `.claude/rules/*.md` sorted, then `AGENTS.md`; `AGENTS.md` wins same-directory contradictions. Optional `CLAUDE.local.md` loads after the checked-in files as a private override. Show both sources; do not claim semantic conflict detection.

Load ancestor instructions on task start; discover nested scope before Read/ListFiles and before Write/Edit/NotebookEdit/Agent delegation. On scoped mutations, resolve instructions natively and return any new guidance before executing so the model can incorporate it. Shell/MCP calls cannot be perfectly path-scoped: load workspace rules and guidance for the active directory, instruct inspection before touching new scopes, and disclose the limitation. Never claim rules physically sandbox an arbitrary approved shell.

Parse @includes as Markdown text, not code or inline-code tokens. Resolve relative includes from the including file; detect canonical-path cycles and aliases. Default to workspace-contained includes; external includes require an explicit configured read grant. Directory traversal for project discovery stops at canonical workspace root; global Taro config is a separate configured source. Frontmatter path globs are relative to the relevant project scope, not string-prefix tests. Re-resolve worktree instructions after EnterWorktree and before resuming children. Include source hash/version in the model context snapshot; recheck before edits, and make changes visible on the next request without duplicating instructions.
