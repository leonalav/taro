# Reception page

Taro starts on a welcome page following the supplied desktop reference: native window controls and brand bar, a centered welcome/composer area, saved work, project starters, quick actions and footer navigation. The existing editor stays mounted while hidden. Its titlebar Home button returns to reception without interrupting running work. The welcome composer also stays mounted, preserving unsent text and attachments; its background animation stops while hidden.

## Actions

- Recent work comes from active saved chats in existing folders, ordered by relative activity labels. Resume selects the actual chat and opens the editor. No sample recent projects are invented to fill the layout.
- The starting composer reuses normal attachments, mentions, skills, permissions and effort controls. Submission creates a fresh chat in the selected workspace before invoking the existing runtime. The old reference chat is not overwritten.
- New project asks for a name and parent directory, creates the folder through the existing native command and opens Explorer.
- Open project uses the native folder picker, reuses an existing workspace when possible and opens Explorer. Cancelling a picker stays on reception.
- Templates are editable starting briefs for a web app, landing page or brand discovery. They do not claim to create template files.
- GitHub import accepts an exact HTTPS GitHub repository URL and a destination parent. It runs a quoted `git clone --` through the existing native shell boundary with a ten-minute limit. Cancellation stops the native request; partial clone files are retained rather than deleted automatically. No remote clone is necessary for automated tests.
- Projects, search and command palette open the existing global picker; selecting a result enters the editor. Ctrl+O opens a project; Ctrl+K and Ctrl+Shift+P open the picker; Ctrl+, opens Settings.
- Docs and What's new provide local product guidance. Settings and account use the existing settings dialog. Notifications accurately show an empty state.

## Visual implementation

The page follows the supplied workspace-wireframe reference: a rounded application frame with a left icon rail, a canvas with a breadcrumb/search bar, a wide hero panel, a saved-work rail on the right, and a bottom row of three action cards. The hero starts directly with Taro's serif welcome lockup: the `NEW SESSION` eyebrow and its workspace-status row are gone, and the left rail has no sparkle/What's new action. The footer's What's new link remains the single updates affordance. Frame chrome, section labels and shortcuts use Geist Mono metadata so the welcome surface reads as the same product as the Explore/Sessions sidebar and the inline artifact sheets.

The accent is monochrome. The only chromatic note on the page is the purple italic "Taro" wordmark and the Taro logo mark; every other accent surface — the primary start tile, the rail's new-project action, the composer border, hover states, spotlights and focus rings — is black, warm ivory or silver. Status colors (green live dot, red errors) stay semantic rather than decorative. The Appearance setting's default accent resolves to that same warm ivory, and the optional user-chosen accent colors remain available in Settings.

The premium pass layers a cinematic backdrop under that wireframe without changing its structure. An aurora of monochrome silver and champagne glass ribbons (`src/assets/reception-aurora.webp`, 29 KB at 1600 px) is anchored to the hero's lower-right edge, scrimmed twice (a linear fade from the panel colour plus a left-to-right mask) and drifted by a 42-second transform-only keyframe. A 10 KB noise tile adds a fine grain over the frame at low soft-light opacity. The display lockup is Instrument Serif at 38–60 px with a gradient italic "Taro", replacing the heavier Merriweather face; document titles in inline artifacts reuse the same serif so the two surfaces rhyme. Metadata pills, suggestion chips and the composer keep opaque surfaces wherever they can overlap the art, so the image never carries text contrast.

Motion is choreographed with GSAP rather than incidental CSS: a single `gsap.context()` timeline lifts the rail, breadcrumb, lockup, subtitle, composer, chips, panels, list rows and footer in reading order, then clears its inline styles so hover and focus CSS own the final state. Panels and start tiles get a pointer-tracked spotlight through CSS custom properties, and a soft warm light trails the cursor inside the hero on fine-pointer devices. Recent, Start something new, Templates and Quick actions all show a low-opacity static silk thumbnail at rest, cropped from the same monochrome hero asset at 12% opacity (14% on start tiles). Hover or keyboard focus raises that layer to 22% (28% on start tiles) and starts a 24-second transform-only drift; hover also reveals the pointer spotlight. Leaving the panel pauses the drift on its current frame while retaining the thumbnail. OS and application reduced-motion preferences remove the drift but keep the static thumbnail; forced-colors removes the decorative layer entirely. Other GSAP entrance effects are skipped in reduced motion, leaving a complete, fully visible page. Layouts reflow at 1080 px (single column), 820 px (rail-first mobile), 560 px (single-column tiles) and 420 px (the breadcrumb yields to the search field). The page, not the panels, owns vertical scrolling so composer popovers are never clipped. Typography remains Geist/Geist Mono for UI and Instrument Serif for display; #0b0b0b surfaces, #1f1f25 hairlines and the monochrome accent remain authoritative. New project and import dialogs preserve input focus across field updates and prevent stale asynchronous responses from updating another dialog.

WCAG 2.2: every shortcut, recent project, template and footer action is a native button with an accessible name, visible 2 px focus ring, and a target of at least 24×24 px (most are 28–40 px). Section headings form an h1 → h2 outline, decorative marks and glyphs are hidden, muted text stays at or above 4.5:1 on the panel surfaces, and status is never conveyed by color alone. The rail scrolls at short viewport heights instead of clipping its actions.

Saved previews: `docs/previews/reception.png` (1672×941, resting thumbnails), `docs/previews/reception-hover.png` (the Start something new panel under the pointer, showing the brighter moving silk layer), and `docs/previews/reception-narrow.png` (480 px). Browser checks confirmed editable template insertion and navigation from a saved project into the IDE. Integration tests exercise primary-model prompt handoff, draft retention, dialog focus, callbacks, GitHub URL validation and the rail/heading accessibility contract; they also assert that the session eyebrow/status chrome and rail sparkle action stay removed. An axe-core audit (WCAG 2.0/2.1/2.2 A and AA plus best-practice rules) reports zero violations on the welcome page at 1560 and 760 px, and on the chat surface with the Explorer panel open and tool rows expanded. A 320 px reflow check reports no horizontal overflow. Reduced-motion renders were inspected with entrance motion cleared and the static thumbnails retained.
